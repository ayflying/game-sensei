# 游戏类型知识库（跨游戏通用）

> 本文件归集**可跨游戏迁移**的类型层知识与操作模式，是 game-sensei 的通用能力资产。
> 对应 `DEVELOPMENT_PLAN.md` §1.1 的「**游戏类型层（可迁移策略）**」。
>
> **归档规则（用户硬性要求）**：
> - 本文件只放**通用**内容——游戏类型的共同规则、节奏、决策模式、可复用操作。
> - **单一游戏的具体玩法、坐标、攻略、数值，一律存 ima 知识库**
>   （「游戏」KB `7504129723208370` → 文件夹 `game-sensei`），不进本仓库。
> - 判断标准：**换一款同类游戏还能不能用**。能用 → 进本文件；不能 → 进知识库。

## 一、类型：换装 / 造型评分类（Fashion dress-up & style battle）

**代表游戏**：Sparkle（详见 ima 知识库 `Sparkle-新手教程流程与界面实测笔记`、
`Sparkle-关卡体系与任务经济实测笔记`）

### 1.1 核心循环

```
选主题  →  按主题从候选部件中挑一件  →  提交  →  评委/进度条反馈  →  结算
   ↑                                                                    │
   └────────────────── 下一轮 / 下一关 ←───────────────────────────────┘
```

### 1.2 三条类型特征（跨游戏稳定）

1. **无自由移动**
   没有摇杆、没有方向键，屏幕不存在「角色位置」这一状态量。
   → **动作空间塌缩为纯点击**，不需要 MOVE / SWIPE / JOYSTICK。

2. **决策本质是「按主题排序候选」**
   给一个主题（场景/风格/场合），给 2~3 个候选，挑匹配度最高的那个。
   隐藏变量是「**部件 × 主题的匹配度**」，这是该类型的唯一核心决策。

3. **反馈分强弱两层**

   | 层级 | 载体 | 特性 | 用途 |
   |---|---|---|---|
   | 弱信号 | 评委文字评语 | 模糊、正向/中性词、无分数 | 语义理解、氛围判断 |
   | 强信号 | 进度条 / 分数 / 星级 | 连续、可量化、即时 | **作为 reward** |

   → **做 reward 一律优先用强信号**，不要试图把评语文本量化。
   → **进度条的颜色常直接编码极性**（实测：绿 = 领先，橙/橙红 = 落后），
   可先做二值化（绿=+1 / 橙=-1）再谈连续量；颜色比长度更稳、更好识别。

4. **奖励随关卡递增 + 新手局加成**
   实测同一游戏内单局收益逐关上升，且**新手首局给得特别多**。
   → 采集样本时别用第一局推算稳态收益。

### 1.3 物品的属性结构

部件通常是**二维属性**，不是一维：

```
部件 = 款式（shape/style） × 颜色（color/palette）
```

同款可换色，且颜色往往也参与主题匹配。
→ 感知层要为「款式」与「颜色」分别建表示，不能只当作一张图。

### 1.4 对抗性选秀（draft）—— 不要当成单人评分

这类游戏很容易被误判为「单人评分」：给几个候选，挑最好的，加分。
**实际多数是零和对抗**：

```
给 N 个候选  →  我选 1 个（归我）  →  对手拿走剩余里最好的那个
```

实测形态：3 个候选，我选走青蕾丝裙后，对手**立刻穿上**剩下的黑哥特裙
（未选中的选项不会保留）。

**策略含义（决策层必须体现）**：

- 目标不是「选一个高分的」，而是**「抢走对手最想要的那件」**
- 选错时对手直接起飞 → **进度条会立刻掉**，这是最灵敏的负反馈
- 因此 reward 是**相对量**（我 vs 对手），不是绝对分

→ 决策模型要拿**对手状态**做输入，不能只看自己。

### 1.5 通用适配要点

- **档案只配 TAP**。给点击类游戏配 move，会让老师模型无限重复 MOVE
  （动作熵极低——在点击类游戏里 MOVE 是无效动作，模型却会抓着不放）。
- **感知重点**：
  1. 当前界面态（几个稳定态可枚举）
  2. 候选件数量与各自热区
  3. 顶部进度条长度（reward 来源）
- **每步先判弹窗，再判主流程**。这类游戏弹窗密度高，漏判必卡死。

## 二、跨类型的通用操作模式

以下模式在多个类型的游戏中反复出现，属**通用能力层**，可直接复用。

### 2.1 弹窗处理（高优先级）

休闲/移动游戏的弹窗密度远高于 PC 单机。实测在一局新手流程内可连续遇到
4 种不同弹窗：服务条款、插屏广告、评分请求、新主题推广。

**处置原则**：

1. **每步动作前先做弹窗检测**，命中弹窗时优先关弹窗，不推进主流程。
2. **不要为每种弹窗写死坐标**。它们的关闭按钮位置各不同（实测 y 跨度 0.20~0.35，
   x 跨度 0.83~0.96），但**形态高度一致：右上角一个圆形 ×**。
   → 应识别「圆形 × 图标」这一视觉模式，而非枚举坐标。
3. **插屏广告是特例**：它由广告 SDK 全屏接管，关闭按钮位置由 SDK 决定
   （实测在 (0.958, 0.023)），通常比游戏内弹窗更靠角。建议单独建一个
   「广告关闭」识别器。
4. ★**广告必须先等播放完才关得掉**。实测：点右上角 × → 等 7 秒 → 截图**仍是广告**
   （画面在播动画）；再等 6 秒后点 × 才成功。
   **同一支广告还会重复出现**（实测同一支插屏出现 2 次）。
   → 自动化对策：**关闭广告必须重试**——点 × 后截图复检，若仍判为广告页，
   等 3~5 秒再点一次，**最多重试 3 次**。绝不点一次就认定关掉了。
5. **弹窗形态**：实测 5 种——服务条款、插屏广告、评分请求（5 星）、新主题推广、
   **Google Play 应用安装广告**（全屏、底部「安装」、右上角 ×，关闭行为同第 4 条）。
6. **弹窗关不掉的兜底**：先试右上角带状搜索区，再试点击空白区，
   最后才考虑返回键。返回键有退出游戏的风险，放最后。

### 2.2 点击类游戏的档案收敛

| 若游戏… | 档案应… |
|---|---|
| 无自由移动 | **不配 keys / move** |
| 纯点击交互 | 只保留 TAP（+ 必要时 PRESS） |
| 有拖拽/缩放 | 才开 SWIPE / ZOOM |

> 反面教材：给纯点击类游戏配上移动键，会直接导致老师动作分布退化。

### 2.3 货币与刷取节奏识别

进入一款新游戏后，**先测「单局收益 / 关键商品价格」**，即可量化刷取成本。

- 记录：单局固定收益、主要商品价格
- 推导：需要多少局才买得起 → 判断是否存在体力/次数限制
- 用途：规划采集样本量（要跑多少局才能覆盖足够的界面状态）
- **「能否无限刷」的实测判据**：连续跑 4~5 局，观察是否出现
  体力条递减、冷却倒计时、或「次数不足」提示。
  若钻石只增不减且无障碍 → 判定**无限制**，可连续采集（对训练样本是利好）。

### 2.4 数值/资源面板的固定读法

移动游戏普遍在三处放资源：
- **左上**：玩家身份（头像、昵称、等级）
- **右上**：硬通货余额（货币、体力）
- **右侧竖排**：功能入口（邮件、商店、相机、地图、通知）

→ 新游戏进场先扫这三处，能快速建立 UI 骨架认知，比逐屏试探快得多。

### 2.5 界面态枚举法（新游戏上手流程）

对新游戏建立认知时，按这个顺序推进最省样本：

1. **走完新手教程**（系统会强制把主要界面过一遍，天然覆盖核心循环）
2. **每步截图存档**，标记状态转移边
3. **回到主界面，逐个点开功能入口**（各截一图）
4. **对高密度区域用网格标定工具读精确坐标**（而不是目测或猜）
5. **跑第二局**，验证状态机是否有未覆盖的分支（如失败结算）

### 2.6 任务 / 订单系统（高频，必有）

休闲/换装/经营类几乎都有「任务列表」，形态高度统一：

```
[角色头像]  任务名                        🔍
           [标签1] [标签2]                 ← 完成条件 = 满足这些标签
           🎁 : 💎 20          [ Accept ]  ← 奖励 + 接取按钮
```

**通用结构特征**：

| 特征 | 说明 | 自动化含义 |
|---|---|---|
| **标签式完成条件** | 要求「穿/带/建出具备某标签的东西」，1~2 个标签 | 需把「标签」纳入物品表示 |
| **刷新倒计时** | 顶部常驻 `Refresh Countdown HH:MM:SS`（实测周期 5~6 小时）| 可预测下一批任务时间 |
| **完成后即消失** | 接取并完成 → 该条从列表移除 | 任务是**消耗性**的，一周期内有限 |
| **奖励分层** | 标签越稀有/越具体，奖励越高（实测 20 → 50 → 120）| 优先做高奖励任务 |
| **底部常留一条锁** | 显示 `Buy VIP to unlock` | 免费玩家槽位被打折（付费点）|

→ 自动化该模块的价值很高：**奖励确定、条件明确、可重复**，比自由探索更容易做出稳定收益。

### 2.7 结算页的「看广告翻倍轮盘」

多数休闲游戏在结算页放一个**倍率轮盘 + 看广告按钮**：

```
       💎 base            ← 基础奖励
  ╭─2x─┬─3x─┬─4x─╮
  │    │    │    │        ← 彩扇标注倍率（实测 2x/3x/4x/5x）
  ╰─5x─┴────┴────╯
    [ ▶ 💎 N ]            ← 按钮上直接写「看了实得多少」
     No,thanks            ← 放弃，只拿基础
```

**识别要点（通用）**：

- 该界面的**基础值**就是关卡固定收益；按钮上的数字 = 加成后的实得
- 这是**免费玩家获取硬通货的主要途径**，也解释了「为什么广告这么多」
- 自动化取舍：看广告耗时且依赖 SDK 可用；**采集样本时建议直接 `No,thanks`**，
  保证节奏稳定（实测模拟器上广告 SDK 常初始化失败，会卡住）

### 2.8 关卡选择器（横向轮播）

常见形态：**一排场景卡横向滑动，居中那张被高亮，打的就是居中那张**。

- 卡片正面 = 场景概念图；卡片上有编号或标签
- **★记住上次浏览位置**：下次进入停在离开时那张，不回起点
  → 自动化需**显式把目标卡滑到居中**（可能要滑多次），不能假设从第一张开始
- ⚠️ **别把卡片上的数字当成关卡号**：实测它可能与进入后顶部的 `Level N`
  不一致（主题名对得上、数字对不上）。**以进入后的界面为准，卡片数字仅作参考**。

### 2.9 找失败条件的探测法

想确定「失败长什么样」，不要随机乱试，用**对照实验**：

1. 正常打一局（选最匹配的）→ 记录结算形态
2. 故意选**明显不匹配**的选项 → 看进度条是否变负、结算是否变 LOSE
3. 若单次选错仍赢 → 说明失败需要**连续多轮选错**，或低难度有保底

> 实测：即使选了明显不搭的部件（进度条掉到橙红），最终**仍然 WINNER**。
> 结论要写成「未观察到 LOSE」而非「不存在 LOSE」——**样本不足不下结论**。
