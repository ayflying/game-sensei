> 本文件归集**可跨游戏迁移**的类型层知识与操作模式，是 game-sensei 的通用能力资产。
> 对应 `DEVELOPMENT_PLAN.md` §1.1 的「**游戏类型层（可迁移策略）**」。
>
> **归档规则（用户硬性要求）**：
> - 本文件只放**通用**内容——游戏类型的共同规则、节奏、决策模式、可复用操作。
> - **单一游戏的具体玩法、坐标、攻略、数值，一律存 ima 知识库**

## 一、类型：换装 / 造型评分类（Fashion dress-up & style battle）

**代表游戏**：Sparkle（详见 ima 知识库 `Sparkle-新手教程流程与界面实测笔记`）

### 1.1 核心循环

```
选主题  →  按主题从候选部件中挑一件  →  提交  →  评委/进度条反馈  →  结算
   ↑                                                                    │
   └────────────────── 下一轮 / 下一关 ←───────────────────────────────┘
```

### 1.2 三条类型特征（跨游戏稳定）

1. **无自由移动**
   没有摇杆、没有方向键，屏幕不存在「角色位置」这一状态量。
   → **动作空间塌缩为纯点击**，不需要 MOVE / SWIPE / JOYSTICK。

2. **决策本质是「按主题排序候选」**
   给一个主题（场景/风格/场合），给 2~3 个候选，挑匹配度最高的那个。
   隐藏变量是「**部件 × 主题的匹配度**」，这是该类型的唯一核心决策。

3. **反馈分强弱两层**

   | 层级 | 载体 | 特性 | 用途 |
   |---|---|---|---|
   | 弱信号 | 评委文字评语 | 模糊、正向/中性词、无分数 | 语义理解、氛围判断 |
   | 强信号 | 进度条 / 分数 / 星级 | 连续、可量化、即时 | **作为 reward** |

   → **做 reward 一律优先用强信号**，不要试图把评语文本量化。

### 1.3 物品的属性结构

部件通常是**二维属性**，不是一维：

```
部件 = 款式（shape/style） × 颜色（color/palette）
```

同款可换色，且颜色往往也参与主题匹配。
→ 感知层要为「款式」与「颜色」分别建表示，不能只当作一张图。

### 1.4 通用适配要点

- **档案只配 TAP**。给点击类游戏配 move，会让老师模型无限重复 MOVE
  （动作熵极低——在点击类游戏里 MOVE 是无效动作，模型却会抓着不放）。
- **感知重点**：
  1. 当前界面态（几个稳定态可枚举）
  2. 候选件数量与各自热区
  3. 顶部进度条长度（reward 来源）
- **每步先判弹窗，再判主流程**。这类游戏弹窗密度高，漏判必卡死。

## 二、跨类型的通用操作模式

以下模式在多个类型的游戏中反复出现，属**通用能力层**，可直接复用。

### 2.1 弹窗处理（高优先级）

休闲/移动游戏的弹窗密度远高于 PC 单机。实测在一局新手流程内可连续遇到
4 种不同弹窗：服务条款、插屏广告、评分请求、新主题推广。

**处置原则**：

1. **每步动作前先做弹窗检测**，命中弹窗时优先关弹窗，不推进主流程。
2. **不要为每种弹窗写死坐标**。它们的关闭按钮位置各不同（实测 y 跨度 0.20~0.35，
   x 跨度 0.83~0.96），但**形态高度一致：右上角一个圆形 ×**。
   → 应识别「圆形 × 图标」这一视觉模式，而非枚举坐标。
3. **插屏广告是特例**：它由广告 SDK 全屏接管，关闭按钮位置由 SDK 决定
   （实测在 (0.958, 0.023)），通常比游戏内弹窗更靠角。建议单独建一个
   「广告关闭」识别器。
4. **弹窗关不掉的兜底**：先试右上角带状搜索区，再试点击空白区，
   最后才考虑返回键。返回键有退出游戏的风险，放最后。

### 2.2 点击类游戏的档案收敛

| 若游戏… | 档案应… |
|---|---|
| 无自由移动 | **不配 keys / move** |
| 纯点击交互 | 只保留 TAP（+ 必要时 PRESS） |
| 有拖拽/缩放 | 才开 SWIPE / ZOOM |

> 反面教材：给纯点击类游戏配上移动键，会直接导致老师动作分布退化。

### 2.3 货币与刷取节奏识别

进入一款新游戏后，**先测「单局收益 / 关键商品价格」**，即可量化刷取成本。

- 记录：单局固定收益、主要商品价格
- 推导：需要多少局才买得起 → 判断是否存在体力/次数限制
- 用途：规划采集样本量（要跑多少局才能覆盖足够的界面状态）

### 2.4 数值/资源面板的固定读法

移动游戏普遍在三处放资源：
- **左上**：玩家身份（头像、昵称、等级）
- **右上**：硬通货余额（货币、体力）
- **右侧竖排**：功能入口（邮件、商店、相机、地图、通知）

→ 新游戏进场先扫这三处，能快速建立 UI 骨架认知，比逐屏试探快得多。

### 2.5 界面态枚举法（新游戏上手流程）

对新游戏建立认知时，按这个顺序推进最省样本：

1. **走完新手教程**（系统会强制把主要界面过一遍，天然覆盖核心循环）
2. **每步截图存档**，标记状态转移边
3. **回到主界面，逐个点开功能入口**（各截一图）
4. **对高密度区域用网格标定工具读精确坐标**（而不是目测或猜）
5. **跑第二局**，验证状态机是否有未覆盖的分支（如失败结算）
