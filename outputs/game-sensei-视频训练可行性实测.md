# 教学视频能否作为学生模型训练素材——实测结论

> 日期：2026-09-13
> 结论一句话：**视频可以当"流程知识"来源（已验证有效），但不能直接当"动作训练真值"（两次实验均模型崩溃）。**

## 一、手上实际有什么（数据盘点）

16 集新手全流程视频（B站 BV1y2dCBKEYb）经抽帧+判读后的产物，位于 `E:/game-sensei-videos/out/`：

| 项 | 数量 |
|---|---|
| 集数 | 16（P01–P16） |
| 原始体积 | 1.2 GB |
| 判读段数 | **1780 段** |
| 关键帧 | **38237 张**（640×360 JPEG） |
| 平均段长 | 19.4 秒 |
| 判读模型 | qwen3.5:9b @ 本地 11435 |
| 捕捉/战斗相关段 | 666 段 |

每段产物结构（`clips.jsonl`）：

```json
{
  "index": 0, "start_at": "00:00:00", "dur_ms": 18500,
  "reps": ["frames/k_000001.jpg", "frames/k_000010.jpg", "frames/k_000019.jpg"],
  "observation": "玩家在城镇石板路上移动…",
  "action":      "使用虚拟摇杆控制角色向前移动，点击右侧中部任务追踪文字自动寻路…",
  "strategy":    "通过点击任务追踪文字实现自动寻路以接近目标NPC…"
}
```

**帧图是干净的纯手游玩法画面**（横屏、左摇杆、右下 star 键），无解说边框，画面域与真机一致。

## 二、尝试：把自然语言判读映射成训练格式

写了转换器 `tools/video_to_dataset.py`，把「操作」文本按关键词映射到学生动作头
（`up/down/left/right/tap/press/wait/none` + tap 坐标），输出 `trajectory.jsonl` + 帧。

**映射率 79.7%（1419/1780）**，看似可观，但人工核对暴露三类失真：

| 失真 | 表现 | 实例原文 |
|---|---|---|
| 斜向被压成单向 | 「向画面**右侧及前方**」「**右前方**奔跑」→ 全归 `up`，导致 up=256 而 down=6 | P02 #3 |
| 复合行为被压成单标签 | 「使用虚拟摇杆移动，**点击**右下角按钮…」→ 归 `tap`，主动作其实是移动 | P02 #0 |
| 判读自身不确定 | 原文写「疑似交互/星形魔法按钮」「推测为交互或菜单」 | P02 #38 |

复合行为段占 **35.5%**——一段 19 秒里通常发生多个动作，强行映射成单一标签等于教错。

**顺带踩到的格式坑**：`trainer/train.py` 的 `map_action()` 认的是**原始轨迹 kind**
（`move`/`key`/`joy`/`tap`），不是目标类别（`up`/`press`）。第一版转换器直接输出目标类别，
导致 `up/down/left/right`（547 条）与 `press`（84 条）被静默丢弃，1472 条只剩 841 条有效样本。
**教训：跨模块对齐字段时，要按消费方的语义输出，不能按自己的直觉。**

## 三、实测训练结果（决定性证据）

| 版本 | 样本 | val_acc | 结果 |
|---|---|---|---|
| video_v1 | 841 | **63.49%（40 epoch 纹丝不动）** | 模型崩溃 |
| video_v2 | 1419 | **52.36%（50 epoch 纹丝不动）** | 模型崩溃 |
| 对照：真机示范 jieyou_v1 | 60 步 | 66.67% | 正常收敛 |

`val_acc` 恒等于某个分类占比（52.36% ≈ tap 占比 51.9%），是 **mode collapse** 的典型特征：
**模型学会"无论看到什么都输出最多数的那一类"，没有任何决策能力。**

对照实验更说明问题：**真机示范只用 60 个样本就达到 66.67%，视频 1419 个样本反而只有 52.36%。**

> **铁律：标签质量 > 数据数量。** 弱标签（推断出来的动作）会主动污染训练。

## 四、根因分析

1. **标签是推断的，不是记录的**——判读报告 `report.md` 自己声明：
   > 「操作」一栏是从画面**推断**出来的弱标签，不是录像中真实记录的操作，**不可作为训练真值使用**。
2. **粒度失配**——段长 19.4 秒，训练样本是「单帧 → 单动作」。段内动作序列被压扁成一个标签。
3. **复合行为占 35.5%**——多动作段无法用单标签表达。
4. **类别极度不平衡**——`tap` 占 51.9%，方向类 `up=256 / down=6`（教程是单向探索流程，天然不均衡）。
5. **方向分布失真**——屏幕上是斜向移动，8 类头只有 4 个基础方向，斜向样本（111 段）只能隔离丢弃。

## 五、可行的正确用法

### ✅ 路线 1：流程知识 → 档案 hints（已见效，继续做）
判读的「局面 + 策略」两栏是有价值的**高层认知**，与动作真值无关。
现有 `nrc.json` 的 8 条先验（star=万能交互键、打残血投咕噜球、克制属性…）就是这么来的。
**这是视频数据当前唯一已被验证有效的用法。**

### ✅ 路线 2：界面状态分类器（弱标签够用）
判断"当前处于什么界面"（探索/战斗/捕捉/菜单/地图/剧情）**从画面本身就能看出**，不需要动作真值。
1780 段可直接作为状态分类器的训练数据，服务于"游戏流程"理解——比硬啃动作标签现实得多。

### ✅ 路线 3：视觉预训练（38237 帧）
用大量无标签帧做自监督预训练，得到通用视觉特征，再用真机示范微调。
数据效率提升明显，且完全绕开弱标签问题。

### ❌ 路线 4：动作克隆 → 必须走真机示范
`helper -demo` 采到的样本带**真实执行的动作**（不是推断），粒度是单帧级。
jieyou_v1 已证明可行（60 步 → 66.67%，tap 误差 0.087）。
**要训操作，就采真机示范；视频帮不上这个忙。**

### 🔧 路线 5：捕捉玩法（666 段）→ 流程状态机，不是动作克隆
捕捉是**跨多段的长流程**（连续块长度 1–25 段不等），且判读粒度看不到"选球→瞄准→投掷"的单次动作。
正确做法：把它做成**状态机 + 宏**（`internal/game` 的 detect/macro 机制），而不是训练数据。

## 七、结论

- **经验有没有总结下来？** 有，但形式是**流程知识与界面认知**（hints + 知识库文档），
  不是可直接训练的动作标签。
- **视频能不能当训练素材？** 作为**动作克隆数据：不能**（实测模型崩溃）。
  作为**流程知识 / 状态分类 / 视觉预训练：能**。
- **下一步最该做的**：要动作就采真机示范（已验证）；视频转去做状态分类器与流程知识沉淀。
