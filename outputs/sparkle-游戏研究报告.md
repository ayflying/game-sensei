# Sparkle 游戏研究报告（持续更新）

> 本文件是 game-sensei 项目对 **Sparkle**（包名 `com.yoyaworld.sparkle`）的学习笔记，
> 属于「游戏适配层」知识。所有结论都来自模拟器真机实测，标注了验证状态。
>
> 平台：MuMu 模拟器 emulator-5554（Android 15），竖屏 **900×1600**（dpi 240）
> 引擎：Unity（`com.singular.unitybridge.SingularUnityActivity`）
> 厂商：YoYa World（`com.yoyaworld.sparkle`）

## 1. 游戏类型判定

**时尚换装 + 评委评分对战（Fashion Dress-up / Style Battle）**。

区别于「解忧梦幻岛」那类种田放置，也区别于「洛克王国」那类 RPG 探索：
- **无自由移动**（没有摇杆/方向键），动作空间收敛为**纯点击**。
- **核心玩法是选择**：在限定时间/轮次内，针对给定主题，从候选部件中挑出「更搭」的那件。
- **反馈来自评委**：每选一次，屏幕上的评委（随关卡换人）给出文字评语，顶部有一条进度条表示当前得分领先/落后。

### 通用能力归属（对照 DEVELOPMENT_PLAN §1.1）

| 能力 | 本项目归属 | 说明 |
|---|---|---|
| 界面/场景识别 | 通用能力层 | 登录页 / 主界面 / 主题选择 / 对战界面 / 结算页 五态可分 |
| 点击交互 | 通用能力层 | 全部操作都是 tap，无 swipe/长按 |
| **选项质量排序** | **游戏类型层（可迁移）** | 换装类共有的「按主题匹配度挑部件」，是这类游戏的核心决策 |
| 部件名 / 坐标 / 主题词表 | 游戏适配层 | 只能放 profile，不进模型 |

**结论**：这类游戏最值得沉淀的是「**看主题 → 看候选 → 挑匹配项**」这个决策模式，
它同样适用于同类换装/装修/搭配游戏。

## 2. 界面状态机（实测截图逐帧确认）

```
[登录页]  Start(游客) / Google / Facebook
    ↓ tap Start
[服务条款弹窗]  「继续」
    ↓
[角色选择]  Choose your character，左右滑动切人，Confirm
    ↓
[主界面 FASHION]  ──┬─→ Dress（衣柜/换装）
                    ├─→ Win VS（进入比赛）
                    └─→ 右侧 5 个功能入口 + 左侧 ADS
    ↓ tap Win VS
[主题/对手选择]  VS 立绘 + 主题名(Street Photo) + 横向主题卡列表 + Start

            / 底部 2~3 个候选部件 / Change 按钮
    ↓ 每轮 tap 候选件 → tap Change → 下一轮
[结算]  WINNER（加分）/ LOSE，底部 Exit
    ↓ tap Exit
[主界面]
```

## 3. 核心循环（已验证一次完整闭环）

1. 主界面点 **Win VS** → 选主题（默认第一张卡）→ **Start**
2. 进入对战，**每轮出现 2~3 个候选部件**（发型 / 配饰 / 衣服 / 鞋 等）
3. 点一个候选件 → 点 **Change** 确认 → 角色外观变化 + 评委给评语
4. 重复若干轮（实测 3 轮即出结果）
5. 结算 **WINNER** → Exit 回主界面

**实测证据（第一局）**：
- 初始钻石 200 → 胜利后 **450**（+250）
- 评委三人在不同关卡会换：第一关 Gus/Dan/Ann，后续 Mic/Evan/Jay
- 顶部进度条会随每次选择变化（绿条 = 领先）

## 4. 已发现的机制要点

### 4.1 广告是流程的一部分
新手教程中途**会插屏弹广告**（实测弹了 War Thunder Mobile 的拼图广告）。
需要点右上角 (0.958, 0.023) 关闭才能继续。
> 影响：自动化流程必须能识别并关闭插屏广告，否则会卡死在广告页。
> 主界面左侧还有常驻 **ADS** 按钮（看广告换奖励），属于可选收益点。

### 4.2 评委评语是弱信号
评语文本（"Trust your gut" / "Could be worse" / "Not too shabby"）是**模糊正向/中性词**，
不直接给出分数。真正的反馈信号是**顶部进度条的长短**。
> 若要让 AI 学会「选得对」，应优先用进度条做 reward，评语只能做辅助语义。

### 4.3 与项目现有动作协议的契合度
- 无需 `MOVE`/`SWIPE`/`JOYSTICK`，档案应**只保留 TAP**（同 `jieyou` 的经验：
  配了 move 会让老师无限重复 MOVE）。
- L1 动作用 `TAP x=<归一化> y=<归一化>` 即可完整表达这个游戏。

## 5. 系统弹窗清单（自动化必须处理）

这类游戏**弹窗极多**，实测一局流程中至少遇到 4 种不同弹窗，
机器人流程必须能识别并关闭，否则必然卡死：

| 弹窗 | 出现时机 | 关闭方式 | 实测坐标 |
|---|---|---|---|
| 服务条款 | 首次启动 | 「继续」按钮 | (0.494, 0.559) |
| **插屏广告** | 新手教程中途 | 右上角 × | (0.958, 0.023) |
| **评分请求**（5 星好评） | 疑似定时/事件触发 | 右上角 × | (0.831, 0.352) |
| **新主题推广** | 回主界面时 | 右上角 × | (0.861, 0.198) |

> ★ 规律：**除了插屏广告，其余弹窗的关闭按钮都在右上角附近**，
> 但坐标各不相同（0.83~0.96, 0.20~0.35）。稳健做法是识别「圆形 × 图标」，
> 而不是写死坐标。

## 9. 已踩的坑

1. **首次运行会崩/闪退**：实测第一次进入后画面完全静止（连续截图字节级相同），
   前台退到桌面 `app.lawnchair`。**force-stop 后重启即恢复正常**。
   初步判断与 Unity Ads 初始化失败（`Trust anchor for certification path not found`）
   或模拟器网络有关，但不影响游戏本体可玩。已记录，未深究。
2. **MuMu 自带 adb 版本较旧**，`adb devices` 会出现 `emulator-5554 offline` 抖动；
   改用 Android SDK 的 adb（`C:\Users\ay\AppData\Local\Android\Sdk\platform-tools\adb.exe`，
   1.0.41 / 37.0.0）稳定。设备号 `emulator-5554`。
3. **每次 adb 调用都会重启 daemon**（输出里反复出现 "daemon not running; starting now"），
   说明有两个 adb 在抢 5037 端口。已统一只用 SDK 版。
