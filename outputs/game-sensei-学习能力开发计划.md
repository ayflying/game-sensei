# game-sensei 学习能力开发计划

> 版本：v1.1
> 编制日期：2026-09-12 ｜ 修订：2026-09-13
> 适用范围：game-sensei 游戏辅助框架
> 总体策略：先打通一个可评测、可纠错、可持续提升的短任务闭环，再扩展到多任务、多游戏和更高自主性。
>
> ⚠️ **编号体系说明（引用时必须带文件名）**：本文件的 **P0–P7 是「单游戏学习曲线」阶段**，
> 与 `DEVELOPMENT_PLAN.md` 的 **P0–P3（工程交付里程碑）不是同一套编号**。
> 对应关系：本 P0–P1 ≈ 交付 P1（数据与教师示范）；本 P2–P3 ≈ 交付 P2（训练与模型治理）；
> 本 P4–P6 ≈ 交付 P3（泛型化）；本 P7 ↔ 交付 P3 的工程化部分。

## 1. 项目现状与核心问题

### 1.1 已具备能力

- 纯视觉感知与模拟输入，不读游戏内存、不接封包。
- PC 与 Android 双后端，统一 backend 接口。
- L1 语义动作与 L2 平台执行动作分层，游戏通过 JSON Profile 配置。
- 老师模型可根据截图输出动作。
- 已落地老师示范、trajectory.jsonl、torch 行为克隆训练、纯 Go 学生前向推理。
- 《解忧梦幻岛》已验证弹窗关闭、签到、点田、打开收获菜单、执行收获。
- 已有窗口感知域、动作打印、重复动作兜底和锁屏检测。

### 1.2 当前主要瓶颈

1. 视觉能力与决策能力没有分离评估，模型能读图但可能重复输出低价值动作。
2. 成功/失败判定不够自动化，无法可靠筛选有效示范。
3. 训练集以顺畅示范为主，缺少学生走偏后的纠错样本。
4. 当前学生更像模仿器，还没有被证明具备跨状态泛化和失败后改进能力。
5. 任务、游戏、平台同时扩展，导致每次改动难以归因。
6. 缺少固定起点、固定测试集、固定版本和统计置信度，容易把“能运行”误认为“学会”。

### 1.3 已实测排除的路径与架构上限（不要再试）

本节每条都有对照实验，目的是**避免重复投入**，不是记录成功：

1. **观测架构上限：单帧灰度图学不会方向。** `up/down/left/right` 的区别在**帧间**而非帧内——
   一个配方从零训到 400 epoch，`up`（12 个训练样本）仍学不起来，方向样本全挤进 `press`/`down`
   （README §11.15）。这是**架构上限，调超参解决不了**。
   ⇒ 在把观测换成**帧差 / 帧对 / 短时序**之前，「提高方向准确率」应视为**被阻塞的指标**，
   不得写进任何阶段的验收条件。
2. **动作克隆不能用视频弱标签。** 1419 条弱标签训两版学生，val_acc **恒定 52.36% / 63.49%**
   （等于各自数据里众数类占比），40–50 epoch 纹丝不动 ＝ mode collapse；而真机示范 `-demo`
   **仅 60 条就有 66.67%**。⇒ **标签质量 > 数据数量**，要动作就采真机示范。
3. **跨域骨干没有迁移价值。** `video_v1` 在视频域自称 52.36%，拿到真机帧上直评是
   **0.00% 且恒输出 `tap`**（README §11.15 配方 A）。⇒「拿视频预训练骨干来加训」目前是
   **待验证假设而非捷径**；要用视频必须先做**域对齐**（同分辨率、同 UI 布局）并单独证明迁移有效。
4. **资料多了不会自动变聪明。** 「数据越多越强」在 LLM 上成立的前提是①标签自带（自监督）
   ②单一任务、统一输出空间 ③数据与参数量同步放大。学生策略头**三条都不满足**：动作标签要人工/老师写、
   输出维度跨游戏语义冲突、网络只有 3 层 CNN（容量天花板低）。
   ⇒ 资料对策略头是**间接**起作用：**资料 → 老师更准 → 示范质量更高 → 学生更强**，
   中间「采真机示范」省不掉。资料能直接兑现的只有两处：**老师上下文（hints/RAG）**与**无标签视觉预训练**。

## 2. 总体目标与非目标

### 2.1 总体目标

建立以下可重复闭环：

```text
任务定义 → 环境重置 → 采集观测 → 老师/学生执行 → 自动判定 → 记录失败
→ 人工或老师纠错 → 训练新版本 → 独立测试 → 保留或回退版本
```

### 2.2 第一阶段目标

以电脑版《解忧梦幻岛》的“找到可收获田地并完成收获”为第一标准任务，实现：

- 可重复重置。
- 可自动判断成功、失败、超时、未知。
- 老师在 20 次试验中成功率达到 80% 以上。
- 学生在未参与训练的起始场景上达到可量化成功率，并与老师、脚本基线比较。
- 至少完成 3 轮“运行→纠错→重训→考试”，验证是否真的变好。

### 2.3 明确不做

- 第一阶段不直接做开放世界自由探索。
- 不急于引入强化学习、奖励模型或更大的模型。
- 不以训练 loss 下降作为唯一成功标准。
- 不把固定脚本成功当作学生成功。
- 不扩展充值、购买、付费、道具消耗等有风险动作。
- 不在没有指标的情况下持续堆积示范数据。

## 3. 工作原则

1. **先评测后优化**：任何优化必须先有基线。
2. **小任务优先**：先做 5~20 步内可闭环任务。
3. **数据分层**：成功示范、失败轨迹、纠错轨迹、未知样本分开保存。
4. **真实证据优先**：代码存在、日志打印、训练完成都不能替代真实端到端测试。
5. **版本可回退**：模型、Profile、提示词、程序版本必须绑定记录。
6. **安全优先**：危险区域和付费控件必须在 Profile 中显式标注并默认禁止。
7. **单变量改动**：每轮尽量只改变数据、提示词、模型、阈值或代码中的一个主要因素。

> 因此本路线图的适用边界是：
> - **P0–P5 不受影响**——《解忧梦幻岛》是**纯点击**任务，动作空间里没有方向类，单帧观测够用。

>   （帧差 / 帧对 / 短时序），并给出「方向类可学」的对照证据。此项已从「调参问题」
>   重新归类为「架构前置条件」。

## 5. P0：评测与任务协议

### 5.1 任务状态机

定义统一状态：

- `INIT`：已准备起始状态。
- `OBSERVE`：取得有效截图。
- `ACT`：执行一次动作。
- `VERIFY`：检查画面变化与任务反馈。
- `SUCCESS`：检测到收获成功或计数增加。
- `FAILED`：检测到任务不可继续、错误状态或危险弹窗。
- `TIMEOUT`：超过总时限或最大步数。
- `UNKNOWN`：证据不足，必须进入人工复核。
- `RESET`：清理并恢复下一次试验。

### 5.2 每次运行必须记录

- run_id、任务名、游戏 Profile、平台、窗口尺寸。
- 程序 commit、模型权重版本、提示词版本。
- 起始截图和结束截图。
- 每步截图、原始模型输出、解析后 L1 动作、L2 动作、实际执行耗时。
- 画面变化分数、重复动作计数、弹窗状态、异常原因。
- 最终状态、成功证据、人工复核结果。

### 5.3 P0 测试

- 单元测试：状态转换、超时、最大步数、重复动作、未知结果。
- 解析测试：正常动作、大小写、中文字段、缺失参数、描述文本误判。
- Profile 测试：未知字段报错、坐标范围、危险控件拒绝。
- 回放测试：使用已保存截图回放，不触碰真实输入。
- 端到端冒烟：人工启动窗口，完成 3 次真实收获。

### 5.4 P0 验收

- 至少 20 次运行均有完整 run 记录。
- 人工抽查 10 次，自动结果与人工结果一致率≥90%。
- 不确定时能进入 `UNKNOWN`，不得强行判成功。
- 任意一次失败可以定位到“感知、决策、执行、验证、环境”五类之一。

## 6. P1：老师可靠示范

### 6.1 示范策略

将任务拆为：

1. 判断主界面、弹窗、收获菜单或未知界面。
2. 识别目标田地。
3. 点击田地。
4. 识别收获菜单。
5. 点击收获。
6. 检查成功反馈。

动作空间只展示当前 Profile 支持的动作。无移动能力的种田任务禁止输出 `MOVE`。

### 6.2 恢复机制

- 连续 3 次相同动作且画面无变化：进入恢复分支。
- 弹窗优先处理，但危险控件必须黑名单拦截。
- 连续 5 次解析失败或 5 次无进展：结束本次运行并保留完整轨迹。
- 不在 `Apply` 内阻塞长时间等待；等待应由状态机调度。

### 6.3 数据质量规则

- 成功轨迹必须有自动成功证据或人工确认。
- **禁止把「推断出的动作」当动作真值**：视频判读、模型推测、人工事后描述都属弱标签，只能进 hints 或
  状态分类集，**不得进动作训练集**（实测会直接导致 mode collapse，见 §1.3 第 2 条）。
- **训练样本必须以「观测窗口」而非「单帧」为单位定义**；在方向类任务上，单帧样本对
  `up/down/left/right` 是不可分的（§1.3 第 1 条），采集格式需预留帧差/帧对。
- 失败轨迹不丢弃，单独标记失败原因。
- 相邻重复截图去重，但不能删除关键状态转移帧。
- 数据集按“起始状态”划分，禁止把同一连续轨迹相邻帧随机拆到训练和测试两边。

### 6.4 P1 测试与验收

- 20 次真实试验，成功率≥80%。
- 平均完成步数、P95 完成时长、无效动作率均有统计。
- 连续失败能自动停止，不污染后续试验。
- 老师不能点击 VIP、购买、充值和危险关闭窗口控件。
- 失败轨迹可人工复盘并归类。

## 7. P2：学生第一版考试

### 7.1 训练数据设计

建议至少准备：

- 100 条以上有效动作样本作为起点。
- 主界面、收获菜单、弹窗、等待、空田地等状态均有覆盖。
- 每个关键状态至少 20 条不同画面样本。
- 失败样本暂不直接混入正向监督集，先作为评测集与纠错候选集。

### 7.2 数据划分

- 训练集：60%。
- 验证集：20%。
- 独立测试集：20%。
- 按运行批次和起始状态划分，不按单帧随机划分。
- 另建“难例回归集”，包括弹窗、遮挡、相似按钮和无进展画面。

### 7.3 对照组

必须同时测：

1. 固定脚本：验证环境和成功判定是否正常。
2. 老师模型：作为上限参考。
3. 学生旧版本：当前基线。
4. 学生新版本：待验收版本。

### 7.4 核心指标

- 任务成功率。
- 独立测试集成功率。
- 平均完成步数与 P95 完成时长。
- 无效动作率。
- 重复动作率。
- 连续无进展次数。
- 人工接管次数。
- 解析失败率。
- 危险动作拦截次数。
- 成功判定准确率、漏报率、误报率。

### 7.5 P2 验收

学生必须在未参与训练的起始画面中完成任务。最低门槛：

- 测试成功率≥60% 才进入纠错学习。
- 若低于 60%，先诊断数据覆盖、标签、动作空间和成功判定，不继续扩大训练量。
- 新版本必须在固定回归集上不低于旧版本；明显退步则自动回退。

## 8. P3：纠错学习闭环

### 8.1 运行流程

```text
学生执行 → 达到成功/失败/超时 → 保存失败轨迹 → 人工或老师指出正确动作
→ 生成纠错样本 → 训练新权重 → 固定测试集评估 → 决定保留或回退
```

### 8.2 纠错样本必须包含

- 学生当时看到的画面。
- 学生输出的动作。
- 实际发生的错误。
- 正确动作及原因。
- 纠错来源：人工、老师、规则。
- 纠错后下一帧及最终结果。

### 8.3 三轮迭代验收

每轮固定记录：

| 轮次 | 新增难例 | 测试成功率 | 平均步数 | 接管次数 | 结论 |
|---|---:|---:|---:|---:|---|
| R0 | 0 | 基线 | 基线 | 基线 | 学生初始能力 |
| R1 | 第一批失败样本 | 待测 | 待测 | 待测 | 是否解决首类错误 |
| R2 | 第二批失败样本 | 待测 | 待测 | 待测 | 是否出现过拟合/遗忘 |
| R3 | 第三批失败样本 | 待测 | 待测 | 待测 | 是否形成稳定提升 |

判定标准：连续 3 轮中，至少成功率提升 10 个百分点、人工接管减少 20% 或 P95 步数下降 15% 之一，同时旧回归集无明显退步。

## 9. P4：多状态泛化与抗干扰

覆盖以下变化：

- 不同田地位置、不同可收获数量。
- 弹窗出现与未出现。
- 收获菜单位置轻微变化。
- 游戏窗口位置变化、缩放变化。
- 局部遮挡、动画中间帧、网络等待。
- 不可收获田地和已经收获田地。

测试分层：

- 正常集：无干扰。
- 轻微变化集：位置、窗口、时间变化。
- 难例集：弹窗、遮挡、相似控件。
- 安全集：危险按钮必须拒绝或请求人工。

通过标准：正常集成功率≥80%，轻微变化集≥70%，难例集至少能安全退出且不得执行危险动作。

## 10. P5：同游戏多任务

第二任务建议选择“领取任务奖励”或同等短流程，要求：

- 新增任务主要通过任务配置和数据完成。
- 核心视觉、动作执行、评测框架不复制一套。
- 任务识别错误时不能执行另一个任务的危险动作。
- 完成第二任务后，第一任务固定回归集不得退步超过 5 个百分点。

## 11. P6：迁移到《洛克王国：世界》

### 11.1 迁移顺序

1. 先选择静态 UI 任务，例如打开菜单、关闭弹窗、点击明确按钮。
2. 再选择短距离移动到固定目标。
3. 最后才尝试连续导航或战斗。

### 11.2 真机要求

- 使用真实 Android 设备和指定 serial。
- 记录横屏下实际截图宽高，不使用物理屏幕方向猜坐标。
- 首先验证 Profile 坐标逐项功能，不把“点得到”当作“功能正确”。
- 默认按 5 FPS 规划，不按 PC 端 30 FPS 估算。
- 每次退出必须释放按住状态。

### 11.3 迁移验收

- 每个按钮至少 5 次逐项真实验证。
- 每个任务有独立成功证据。
- 失败时可以回到安全状态。
- 未完成验证的坐标和功能必须标记为未核验，不进入训练正集。

## 12. P7：工程化与扩展

### 12.1 任务包标准

每个游戏任务包包含：

- Profile JSON。
- 任务定义与状态机。
- 允许动作白名单。
- 危险控件黑名单。
- 成功/失败判定器。
- 数据集版本。
- 学生权重版本。
- 固定回归集。
- 真实测试报告。

### 12.2 模型注册

为每个学生权重记录：

- 游戏、任务、平台。
- 训练数据版本。
- 代码 commit。
- 训练参数。
- 训练时间。
- 验证指标。
- 独立测试指标。
- 是否为当前 active 版本。
- 回退原因。

### 12.3 回归门禁

任何代码、Profile、提示词或权重修改，都必须至少运行：

- Go 单元测试。
- Profile 解析测试。
- 轨迹回放测试。
- 固定测试集推理。
- 必要时进行真实端到端冒烟。

## 13. 测试总方案

### 13.1 测试金字塔

1. 解析器和动作转换单元测试。
2. Profile schema 与安全约束测试。
3. 纯截图回放测试。
4. 学生推理 parity 测试：Go 与 torch 输出误差必须在既定阈值内。
5. 模拟输入集成测试。
6. 真实窗口 PC 测试。
7. Android 真机测试。
8. 长时间稳定性测试。

### 13.2 每轮测试记录模板

- 测试日期、操作者、机器、游戏版本。
- 仓库 commit、Profile 版本、权重版本。
- 测试集版本和样本数。
- 成功/失败/超时/未知数量。
- 失败分类及前三大原因。
- 与上一版本差异。
- 是否通过回归门禁。
- 后续行动项。

### 13.3 稳定性测试

在通过功能门禁后运行至少 30 分钟或 100 个短任务循环，关注：

- 内存增长。
- GDI/ADB 资源泄漏。
- 按键卡住。
- 窗口失焦。
- 连续截图失败。
- 模型请求超时。
- 轨迹文件损坏。
- 学生动作分布退化为单一动作。

## 14. 风险与应对

| 风险 | 早期信号 | 应对 |
|---|---|---|
| 老师低熵重复 | 重复动作率高、无进展 | 缩小动作空间、加入阶段状态、限制重试 |
| 学生学会中心点击 | 测试位置变化立即失败 | 增加位置和状态覆盖，按场景划分数据 |
| 成功判定误报 | 截图看似变化但任务未完成 | 引入计数/菜单/多证据判定 |
| 训练集泄漏 | 随机帧准确率高、独立测试低 | 按运行和起始状态切分 |
| 纠错样本污染 | 新版本回归退步 | 纠错来源分级，固定回归集门禁 |
| 弹窗误点危险控件 | 出现 VIP/购买点击 | 黑名单、动作白名单、人工确认 |
| Android 坐标错位 | 横竖屏尺寸不一致 | 以缓存截图尺寸为准，真机逐项核验 |
| 长动作阻塞 | FPS 下降、回路停顿 | 异步按住、代次刷新、退出 ReleaseAll |
| 环境变化 | 窗口尺寸/版本变化 | 版本绑定、重置检查、未知状态安全退出 |

## 15. 版本与提交策略

每个阶段结束时形成一个可回退节点：

- 代码 commit：中文提交信息，限定本次涉及文件。
- Profile 版本：独立记录变更原因。
- 数据集版本：新增、删除、修正样本可追溯。
- 权重版本：训练参数与指标齐全。
- 测试报告：记录真实结果，不用代码检查替代。
- README：已确认接口、限制、实测数据同步更新。

禁止：

- 直接覆盖旧权重而不留版本。
- 把失败样本静默删除。
- 把模拟回放结果写成真机结果。
- 把训练准确率写成任务成功率。
- 使用无法确认来源的外部坐标或攻略作为真实验证。
- 把推断出的动作（视频判读/模型推测/事后描述）当作动作真值写入训练集。
- 在未引入任务条件输入的情况下，把多游戏动作样本混入同一个策略头。
- 把「共享视觉骨干」当作已有能力——跨域迁移尚未验证（§1.3 第 3 条）。
- 把堆积示范数据当作能力提升手段；数据量不能替代标签质量（§1.3 第 2 条）。

## 16. 立即执行顺序

第一轮严格按以下顺序：

1. 固化“解忧梦幻岛收获任务”定义。
2. 实现或补齐运行记录与状态机。
3. 建立 20 次真实基线。
4. 统计失败分类，不先改模型。
5. 修老师重复、弹窗恢复和成功判定。
6. 重新采集合格示范。
7. 训练学生 V1，并在独立测试集考试。
8. 采集学生失败轨迹，完成 R1 纠错训练。
9. 进行 R2、R3 迭代，并保留每版指标。
10. 只有达到门槛后，进入多状态、多任务和洛克王国迁移。

## 17. 最终完成定义

本项目不能以“模型能输出动作”或“训练脚本能运行”作为完成。第一阶段真正完成必须同时满足：

- 任务可重置、可运行、可判定、可回放。
- 老师能稳定产生高质量示范。
- 学生在独立起始状态上完成任务。
- 失败能沉淀为纠错数据。
- 至少三轮重训后有可重复的指标提升。
- 新版本不会破坏安全约束和既有回归集。
- 所有结论都有真实测试记录和明确限制。

这套门槛通过后，才进入下一游戏或更复杂任务。
