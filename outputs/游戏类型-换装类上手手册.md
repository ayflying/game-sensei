# 换装类游戏上手手册（拿到新游戏直接照做）

> 目标：**下一款换装游戏从冷启动到 plan 线跑通，不再重新踩坑**。
> 样本：Sparkle（关卡推进型）、YoYa Star: On Air（房间枢纽型 + 直播壳，14 项玩法全覆盖）。
> 类型特征与决策层理论见 `outputs/game-sensei-游戏类型知识库.md` §1.1~1.8；
> 自动化执行层通用坑见 §4.1~4.10。本手册只写「操作顺序」与「结构模板」。

## 一、换装类的两种界面骨架（拿到新游戏先对号入座）

### 骨架 A：房间枢纽型（YoYa Star、多数社交换装）
主界面是一个「房间/卧室」，角色居中，**入口以图标环绕四周**：
- 典型 10 入口：头像(Settings)、通知、内购 Store、看广告商店、任务/奖杯、POSE、直播、发帖/社区、自由换装、PK 对决。
- **识别特征**：图标无文字或文字极简、多个入口视觉相近。
- **必做**：入口枚举 + 像素扫描标定（见 SOP 第 2 步）；警惕「同名不同义」（实测 ADS≠SHOP、通知=直播邀请、LIVE SHOW=直播中换装）。

### 骨架 B：关卡/地图推进型（Sparkle）
主界面是地图或关卡列表，角色头像逐格移动 = 进度。
- **识别特征**：有关卡号牌、剧情线与对战线可能并行（§1.6）。
- **必做**：先判「当前在哪条线」（二值胜负线 vs 星级评分线），两线结算 UI 不同、判据不能混用。

两种骨架共用同一套底层循环：**选主题/场合 → 按匹配度挑部件 → 提交 → 强信号反馈**（§1.1）。

## 二、上手 SOP 七步（每步的产出物明确）

| 步 | 做什么 | 产出物 | 工具/要点 |
|---|---|---|---|
| 1 | 冷启动 + 新手链观察 | 新手链步骤坐标表 | 真机优先（模拟器教学环节可能假卡死，§4.7）；教学会吞输入属正常，走完或 force-stop 跳过 |
| 2 | 入口实测枚举 | 入口坐标表（归一化） | `find_btn.py --preset room` 像素扫描质心；**禁目视估坐标**（误差 0.06~0.14，§4.9） |
| 3 | 玩法清单法逐入口点测 | 玩法覆盖清单 + 数值表 | 每入口记录：入口名/真实功能/坐标/货币变化/广告触发；数值随手记（收益、价格、门槛） |
| 4 | 判据设计 + 反例验证 | 判据表（从档案 JSON 读） | 每条判据**必须与反例帧比分离度**（广告帧/其他页面，§4.8）；小控件用区域色占比不用全局 Δ（§4.10） |
| 5 | 建档 `profiles/<名>.json` | 档案 + `go build` 重编译（go:embed） | **从模板复制**：`internal/game/profiles/dressup_common.json`（14 步 PK 主循环骨架，用法见 `docs/dressup-template.md`）；只配 TAP（§1.8） |
| 6 | plan 线跑批 | result.json + 胜负统计 | `plan_round.py`（FAIL 双证据）+ `batch_plan.py`；未决不计分母；粘住广告记 UNDECIDED |
| 7 | 收尾判定 | 文档章节 + 知识归档 | 收尾口径 §1.6 五条：①真机端到端 ②胜率 ③抓帧重试 ④文档 ⑤判据捕获败局 |

**节奏提醒**：第 3 步不要省。YoYa Star 的三条「卡点」全是第 3 步没做透、后期误判成「注入被吞」。

## 三、判据模式库（换装类实测有效的五件套，全从档案 JSON 读）

| 判据 | 模式 | YoYa Star 实测参数 |
|---|---|---|
| 场景探测器（我在哪） | 独有色块占比 | 票数条 (255,140,250)t50：广告 0.0% / 主界面 0.7% / 结算 47~50% |
| 入口守卫（防广告假判） | 用场景探测器做 `when` | 第 12 步 when=票数条≥0.10，金冠挪 until |
| 胜利判据 | 结算大字纯色占比 | VICTORY 白 t4 ≥0.07（胜 11.6~12.3% vs 负 2.8%） |
| 失败判据 | 反差色小图标 + 双证据 | 金冠 (255,200,60)t45 4.4% + 票数条在场，两条件同时成立才判负 |
| 流程判据 | 深色带/卡片灰区间 | THEME 深色带 (19,19,19)≥0.30；选装卡灰 ≥0.35↔≤0.20（min/max 夹逼） |

**三条铁律**：①末步永不带 `when`（整步跳过=退出码 0 假成功）；②否定类结论双证据；③「双向一致」≠判据正确（§4.8）。

## 四、换装类陷阱速查（新游戏按此核对）

### 广告体系（最大干扰源，每款几乎必现）
- 插屏几乎每个页面跃迁都弹；**不自动消失**；AdActivity 挂游戏包名下（前台包名检查失效）。
- 粘住型广告（无关闭钮、返回键无效）⇒ 只能 `am force-stop` + monkey 复位。
- 广告创意会污染颜色判据：黄色横条顶高金色判据（假判负事故）、浅色创意顶高卡片灰（假选装）。
  ⇒ 守卫判据必须选**广告帧占比≈0 的色块**，判据上线前跑反例帧矩阵。
- 铁律：绝不点广告区域坐标；返回键只在守卫判据确认已离开广告时按；「打开/Visit Site」绝不点。

### 注入与交互
- 结算页「已领奖」态可能**拒绝一切注入输入**（只认真人触摸）⇒ plan 终点停结算页，复位走冷启动。
- 判「点击被吞」三步排除法（§4.10）：crop 放大核对坐标 → 局部 Δ/色占比 → 才允许判「拒绝注入」。
- 弹窗/浮层关闭优先级：**点面板外空白区 > X 按钮 > 系统返回键**。

### 数值体系（换装类通用记账单位）
- 主货币通常一种（爱心/金币/钻石），来源：PK 胜局、直播、发帖收赞、任务 Claim。
- 内购三档常见：去广告买断（$1.99~）/ 月卡 VIP / 高档 SVIP；订阅中心常跳系统页（非游戏内）。
- 看广告解锁类功能（套装/翻倍）= 免费变强主途径，也是自动化最常卡的地方 ⇒ 奖励广告流程必须单独立步。

## 五、下一款换装游戏的待验证假设（样本只有 2 个，以下按「大概率成立」对待）

1. 主界面入口 ≤12 个、全部可像素扫描标定 —— 若入口藏二级页，先点开一级再扫。
2. 主题每局随机、候选类别随主题变 ⇒ 档案不能写死候选位置以外的内容；选装用幂等点击+短超时。
3. 一局关数不固定（实测 2 关，样本 6/6 但非硬保证）⇒ 流程步按「幂等+循环」设计，不写死关数。
4. 结算页胜负大字/徽章是最稳的判负判胜载体；票数条、人气条等彩色条 = 最佳场景探测器。
5. 新手链教学模态吞输入 ⇒ 首次进游戏先手动/半自动走完新手链，再开始自动化采集。
6. 广告密度只增不减 ⇒ 档案里「清广告步」作为标配，主流程每 2~3 步插一次。
