## 11.5 ⚠️ 实测坑：锁屏/系统 UI 前台会让 GDI 会话失效（2026-09-12）

锁屏（LockApp，类名 `Windows.UI.Core.CoreWindow`）在前台时：

1. `SetForegroundWindow` 对任何普通窗口都失败（前台锁 + 锁屏在独立桌面）；
2. `SendInput` 的点击会**落在锁屏上**，触发锁屏过渡——过渡期间本进程的
   GDI 句柄批量失效，`BitBlt` 连续报 `The handle is invalid`（重试也失败，
   等锁屏稳定后自动恢复——是会话级状态破坏，不是句柄泄漏）。

防御（已实装）：helper 启动时 `gamewin.ForegroundIsSystemUI()` 检查，
前台是锁屏/系统 UI 直接拒绝启动；demo 循环抓屏失败自动重试 2 次（应对偶发抖动）。

## 11.6 窗口感知域：把截屏/点击/送审收敛到游戏窗口（2026-09-12）

窗口化游戏（微信小游戏 427x782）嵌在 1920x1080 桌面里，全屏感知双重劣化：
老师 1024 宽送审帧里游戏只占 28%（实测被描述成「手表表盘」），学生 160px
灰度观测里游戏只剩 45px 噪声。

解法（`-game` 档案模式自动启用，无需新参数）：

- 启动置顶游戏窗口后 `gamewin.ClientRectByTitle` 取**客户区**矩形
  （排除标题栏/边框），注入 `pcBackend.SetWindowRegion`；
- `capture.GrabRegion/GrabColorRegion` 只抓窗口子矩形；
- `input.Actuator.Offset` + 窗口尺寸注入：归一化坐标 = 窗口域，
  `pixel()` 换算后加窗口原点得屏幕绝对坐标；
- 档案按钮 `pos` 从此全部按**窗口归一化**填写（与感知域一致）。
  ⚠️ 旧档案按全屏标定的坐标需重新标定。

## 11.7 ⚠️ 实测坑：日志浮窗与 GDI 抓屏互斥挂死（2026-09-12）

浮窗开启时第一次「Hide→BitBlt→Show」整进程挂死（最小探针复现；
卡点在 user32/GDI 交互，未深究）。**`-overlay` 默认已改 false**，
需要日志用 `... > run.log 2>&1` + `tail -f`。此前「demo 采集挂死」
的元凶就是它——当时误判为 Ollama/网络问题。

## 11.8 ⚠️ 实测坑：9B 老师的「复读机」与强制轮换兜底（2026-09-12）

解忧梦幻岛实测：PrevAction 喂回 + 提示词禁令都压不住 qwen3.5:9b
重复同一坐标（20+ 步连点，甚至误点 VIP 弹出 30 元付费弹窗）。

兜底（已实装 `cmd/helper/demo.go`）：连续重复 ≥3 步时跳过老师决策，
按 `step % len(buttons)` 轮换档案按钮强制执行（日志标「强制」），
用状态多样性弥补动作多样性。**小模型提示词禁令不可信，程序级兜底才可靠。**

> 2026-09-13 更新：这条兜底后来**按动作种类细分**了——移动（`MOVE`）不再适用
> 「≥3 步就换按钮」（走远本就要连续同向），且卡住时改为**换方向**而非换按钮。
> 见 §11.10。
