### 1.3 录屏黑边（关键换算）

所有帧上下各有 **48px 纯黑边**（480p 时）：

```

真实画面 852 × 384   (y0=48, y1=432)  → 宽高比 2.219
```

**任何 OCR 坐标必须先扣黑边再归一化**，否则与真机坐标系统性偏移。归一化公式：

```python
nx = cx / 852
ny = (cy - 48) / 384
```

## 二、玩家时间都花在哪（玩法权重实证）

由 4,118 帧的界面分类统计（按时间序**连续采样**，可近似代表时间占比）：

| 界面类型 | 帧数 | 占比 |
|---|---|---|
| 大世界探索 / 其他 | 1,927 | **46.8%** |
| 任务 / 手册 / 作业面板 | 1,112 | **27.0%** |
| 战斗 | 292 | 7.1% |
| 剧情对话 | 230 | 5.6% |
| 队伍宠物 / 精灵详情 | 222 | 5.4% |
| 商店 | 87 | 2.1% |
| 角色属性 | 68 | 1.7% |
| 家园 | 67 | 1.6% |
| 背包仓库 | 42 | 1.0% |
| 地图 | 33 | 0.8% |
| 捕捉 | 21 | 0.5% |
| 登录加载 / 设置 | 17 | 0.4% |

**结论（对自动化策略的直接指导）**：

1. **这不是一款以战斗为核心的游戏。** 战斗只占 7%，大世界跑图 + 任务面板合计 **73.8%**。传统"找怪→进战斗→打怪升级"的思路在这里权重极低。
2. **任务/手册面板是第二高频界面（27%）**，说明大量时间在**读任务、对进度、开手册**。对 AI 来说，"识别当前课题与进度"比"打赢一场战斗"更有价值。
3. **捕捉界面只有 0.5%** —— 捕捉动作本身极短（在大世界直接投球，无需进战斗），这从数据层面印证了此前"大世界直接丢球、不必进战斗"的结论。

界面转场 Top（相邻关键帧）：

```
其他 → 其他 1193     任务 → 任务 705      任务 → 其他 271
其他 → 任务 256      其他 → 战斗 148      战斗 → 其他 138
其他 → 对话剧情 102   对话剧情 → 其他 93    队伍宠物 → 其他 90
```

⇒ 主循环是 **大世界 ⇄ 任务面板** 的自循环，战斗/对话/宠物面板均为**短时插入**。

### 5.1 赛季作业结构

```
完成赛季作业第二章的3个课题（2/3）
完成赛季作业第三章的4个课题（2/4）
```

⇒ **赛季作业按章推进，每章含 3~4 个课题，需逐个完成**。课题数逐章递增（第二章 3 个 → 第三/四/五章各 4 个）。

入口：左上角功能栏 `对战系统` (0.117, 0.046)；子页 `星光对决` (0.126, 0.082)。

**星光对决「养成同步」机制**（`P127_f00124` 原文）：

> 参加星光对决精灵的等级、成长次数和成长值会被**重置为精灵盒子中精灵的最高养成水平**

## 十一、可复用工具链

本次学习的全部脚本位于 `.workbuddy/nrc/video_learn/`（Python，非正式 Go 实现，仅作分析工具）：

| 脚本 | 作用 |
|---|---|
| `downloader.py` | B站合集并发下载（**仅下视频流**，绕开沙箱 safe-delete 门禁） |
| `extract.py` | 抽帧（`--watch` 支持边下边抽；`--width 0` 保持原始分辨率） |
| `dedup.py` | 感知哈希去重（16×16 灰度 + 4×4 RGB 双签名 + 滑动窗口） |
| `ocr_batch.py` | RapidOCR 批量中文识别 + 黑边检测 + 坐标归一化 + 界面分类 |
| `screen_catalog.py` | 界面聚类（Jaccard 0.42） |
| `ui_atlas.py` | UI 坐标图谱（跨帧文字位置聚类） |
| `extract_knowledge.py` | 按主题正则抽取代表性画面与高频术语 |

**经验**：
- 抽帧**不要降采样**：1170px 宽时 OCR 命中 8/9，降到 720px 只剩 2/9。
- RapidOCR 比 VLM 判读**快约 100 倍**，适合全量覆盖；VLM 只用于纯画面语义（动作、动画）。
- OCR 对字形相近的字有稳定误识：`捕→捅/提`、`魔法师→法师`、`队伍→队伍/从伍`、`第X章→第X童/享`，检索时需做模糊匹配。
