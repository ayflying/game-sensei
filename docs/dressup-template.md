# §13 换装类通用玩法模板（量化判据驱动）

> **模板档案**：`internal/game/profiles/dressup_common.json`（内置，`-game dressup_common` 可加载）。
> 它把换装类（房间枢纽型）的通用玩法固化成**机器可读的 plan 档案**——由 `internal/plan`
> 执行器按像素判据零模型跑完，不依赖知识库文档或大模型。文档只解释这份配置怎么复用。

## 13.1 模板是什么

一份**参数化的玩法骨架**：18 步 PK 主循环（14 步骨架 + 4 个选装前缓冲步，2026-09-16 二次修复加入）+ 7 个按钮 + 22 条 hints。
所有坐标与判据阈值取自 YoYa Star 真机实测默认值；换游戏时**只换参数、不换结构**。

骨架五段（跨换装游戏稳定的部分）：

| 段 | 步骤 | 量化驱动机制 |
|---|---|---|
| ① 入口步 | 点 PK 入口 → 深色带判据确认到 THEME 页 | ratio 判据 min_ratio=0.30，strict 诚实失败 |
| ② 清广告循环 ×4 | 票数条 <0.05 才按返回键（广告 0.0% 绝不误触） | 守卫判据 `when` + `max_repeat` |
| ③ 选装幂等步 ×4 | 三选一固定相对位置点按，有卡片才点；**每步前置一个「等 1s」WAIT 缓冲步**（页面刚加载的注入点击会被吞，s30~s34 实据） | `when` 卡片灰 ≥0.35 ↔ ≤0.20 夹逼；循环补点 `max_repeat 5 / gap 2s` |
| ④ 判负闸门 | 金冠在场 + 票数条守卫 ⇒ strict 主动失败 | FAIL 双证据，防广告色块假判 |
| ⑤ 判胜末步 | VICTORY 大字白占比 ≥0.07，**不带 when** | 末步 strict 防假成功（退出码 0） |

## 13.2 复用流程（新换装游戏上手第 5 步）

1. **复制**：`cp internal/game/profiles/dressup_common.json internal/game/profiles/<游戏名>.json`
2. **重标定**（四件事，工具在 `.workbuddy/yoya-star/phone/`，方法见 §12.16）：
   - `package` 填新游戏包名（模板刻意留空，防止误触 `am force-stop` 空包名）；
   - 7 个按钮 `pos` 用 `find_btn.py --preset room` 像素扫描质心重定；
   - plan 里每条 `ratio` 判据的 `region / color / tolerance / min_ratio` 按 `px.py`
     对「目标页 + 反例帧（广告/其他页面）」实测重定——**判据必须与反例帧可分离**（§12.13）；
   - `plan.name` 改成新游戏名。
3. **重编译**：`go build ./...`（go:embed，改 JSON 必须重编译才生效）。
4. **验证加载**：`go run ./cmd/helper -game <游戏名>`（解析与 normalize 校验立即报错）。
5. **真机小步跑**：先 `-plan` 单步预算跑通 ①→②，再放开整条（见 §12.14 跑批口径）。

## 13.3 模板自带的量化默认值（换游戏时逐条核对）

| 判据 | region | color | tol | 阈值 | 语义 |
|---|---|---|---|---|---|
| THEME 深色带 | [0.14,0.10,0.86,0.15] | (19,19,19) | 12 | ≥0.30 | 到达主题选择页 |
| 选装卡片灰 | [0.15,0.730,0.85,0.800] | (238,241,245) | 10 | ≥0.35 / ≤0.20 | 卡片出现/消失 |
| 票数条（守卫） | [0.20,0.090,0.50,0.115] | (255,140,250) | 50 | <0.05 才按返回 / ≥0.10 入守卫 | 场景探测器 |
| 判胜 VICTORY | [0.14,0.15,0.86,0.20] | (255,255,255) | 4 | ≥0.07 | 胜局大字 |
| 判负金冠 | [0.840,0.022,0.915,0.065] | (255,200,60) | 45 | until max_ratio 0.005 | 败局徽章 |

⚠️ 这些数值是 YoYa Star 的画面实测，换游戏**必须重测**——结构可复用，颜色分布不可复用。

## 13.4 与知识体系的关系

- **配置（本模板）** = 量化模型驱动的可执行玩法 → 进 git、进二进制（go:embed）。
- **手册**（`outputs/游戏类型-换装类上手手册.md`）= 怎么把新游戏填进模板的 SOP。
- **实测笔记 / ima 知识库** = 参数的出处与事故复盘，供查阅，不参与运行。
